# 登攀 / TOZANBU

ランダム生成された山を 1〜複数人で登り、山頂を目指す 3D 登山ゲーム。
未踏峰を最初に登頂したパーティーには命名権が与えられ、その名前と初登頂記録が全プレイヤーに共有される。

**同じことをスケールを変えて3回やる**ゲームにしてある。

| スケール | 見るもの | 判断 |
| --- | --- | --- |
| 山ぜんたい | 地形図の等高線 | どの尾根を使うか／どちらから回り込むか |
| 斜面 | 目の前の3D地形 | どこが歩けてどこが壁か |
| 岩壁 | 岩肌の難易度 | どのセルを繋いで登るか |

どれも「ルートファインディング」で、判断の材料だけが違う。

Three.js + TypeScript + Vite / マルチプレイと永続化は Cloudflare Workers (Durable Objects)。

## 起動

```bash
npm install
```

ソロで遊ぶだけならこれだけでよい。

```bash
npm run dev
```

開発中に地形だけ確認する場合:

```bash
npm run dev
# ブラウザで http://localhost:5173/terrain-preview.html
```

マルチプレイと山の記録のサーバを使う場合は、別のターミナルで:

```bash
npm run dev:mp
```

`npm run dev` は `/api` と `/ws` を `127.0.0.1:8787` へプロキシする。
サーバを起動していない場合、山の記録は自動的に localStorage へフォールバックし、ソロで問題なく遊べる。

その他のコマンド。

| コマンド | 内容 |
| --- | --- |
| `npm run typecheck` | クライアントと Worker の型検査 |
| `npm run test:mp` | wrangler dev を立ててマルチプレイと記録 API を検証 |
| `npm run test:terrain` | 骨格地形の決定論性・到達可能性を検証 |
| `npm run build` | 型検査 + 本番ビルド (`dist/`) |
| `npm run deploy` | ビルドして Cloudflare へ配信 |

## ブリーフィング

ゲーム開始時、ローディング画面の代わりに**地形図**を出す。
地形の生成が終わると「準備完了」ボタンを押せる。ソロでは押した時点で、
マルチプレイでは全員が押した時点で登山を開始する。30 秒経過時は未準備でも自動で開始する。
マルチプレイでは全員が同じ地形図を見ながら大まかなルートを相談する時間になる。

```
山生成・ロード
      ↓
┌──────────────────┐
│  BRIEFING   00:30  │
│                    │
│      等高線図       │
│                    │
│  登山口      ▲山頂 │
└──────────────────┘
      ↓
登山開始
```

登山中は `M` で地形図をいつでも開ける。ピンとルート線はブリーフィング時のまま表示される。
地図表示中は移動が止まり、もう一度 `M` で閉じると登山を再開する。

登頂後は即座にゲームが終わらない。**下山して帰還**を選ぶと登山口への帰還が目的になり、
到着すると下山完了画面が出る。山頂から**タイトルへ**戻るショートカットも残している。
下山完了はローカルプレイヤーの旅程のみで、マルチプレイの同期対象にはしない。

地図はクリックでピン、ドラッグでルート線を描ける。
パーティー全員に共有され、各自の色で表示される。

### 3Dの山と地形図は同じ標高データから作る

```
Seed
 ↓
Heightfield
 ├─ 3Dの山岳地形
 └─ 2Dの等高線地形図
```

等高線は Heightfield をマーチングスクエアで切ったもの。**同じ数値を見ている**ので、
地図で等高線が密な場所は実際にも急斜面になる。地図を読む意味があるのはそのため。

| 地図の等高線の濃さ | 実際の傾き (同じ27m四方で計測) |
| --- | --- |
| 薄い (下位20%) | 29.3° |
| ↓ | 38.6° / 41.2° / 42.5° |
| 濃い (上位20%) | 42.8° |

地図に載せるのは**地図の縮尺で判別できるものだけ**。

| | 内容 |
| --- | --- |
| 等高線 | 主曲線 5m または 10m ごと（山の高さで切り替え）。計曲線は5本ごとに太く、標高を入れる |
| 稜線 | 主稜線 (実線) と支尾根 (破線)。骨格から描く |
| 谷 | 破線 (青系)。尾根間の谷・沢の目安 |
| 鞍部 | 小さな輪。副峰を越すか巻くかの中間目標 |
| 副峰 | 小さな ▲ と標高 |
| 崖 | ケバ（下り方向へ伸びる短い線）。8m 四方で見て「立てない斜度」の所だけ |
| 山頂 | ▲ と標高 |
| 登山開始地点 | ● 登山口 |
| 方角 | 北は -Z。地図の上が北 |
| 縮尺 | 100m のスケールバー |

岩肌の難易度・クラック・小さな段差は**載せない**。そこは実際に取り付いてから見て決める。
崖の判定にはゲームと同じ「立てない斜度」を使うが、1m の格子でそのまま測ると段差のたびに反応するので
8m のブロック単位で測る（＝地図の縮尺で意味のある崖だけが出る）。

### 計画は強制しない

登山開始後、ブリーフィングで決めたルートに縛られることはない。
実際の山を見ながら自由に変更できる。
**地形図上の計画と現地の判断が完全には一致しないこと**をゲーム性とする。

## 操作

操作キーは必要最小限にする。地形との関係で同じ入力の意味が変わる。

| 入力 | 通常時 | 登攀中 |
| --- | --- | --- |
| `W` `A` `S` `D` | 移動 | **手を出す方向を選ぶ**（斜めも可） |
| `Space` | ジャンプ／段差ではマントリング | **その方向へ1手登る** |
| `S` 長押し（1秒） | — | 手を放して落ちる |
| `Shift` | ダッシュ | — |
| `M` | 地形図を開く／閉じる | — |
| マウス移動 | 視点（ポインタロック） | 視点 |
| 左クリック | 視点をロック | — |
| 右クリック | — | ロープを固定する |
| 左ドラッグ | 視点を回す（ロック不可の環境） | 同左 |
| ホイール | 寄る／引く | 寄る／引く |

- 岩壁に正面から `W` を押し当て続けると、専用キーなしで登攀へ移行する。
- 方向は**画面基準**。壁をどちら向きに見ていても `D` は画面の右へ手を出す。
  壁を真横から見る向きでは左右の判定が揺れるので、はっきり向きを変えたときだけ切り替える。
- 登攀中はカメラが**掴んでいるセルの高さ**を画面中央に置く。
  八方すべての行き先が画面に入るようにするため（目線を中央にすると下が切れる）。
  レティクルは通常移動のときだけ出す。
- 壁の下端で `S` + `Space` を押すと地面へ降りる。
- ポインタロックが許可されない環境（埋め込み表示など）では、ドラッグで視点を回す。
- 登山中は `M` でブリーフィングの地形図を再表示できる。下山中も同様。
  地図表示中はシミュレーションが一時停止し、閉じるとポインタロックが再要求される。

## 7つの基本アクション

歩行・ダッシュ・ジャンプ・マントリング・登攀・トラバース・落下。
滑り／しゃがみ／匍匐／壁走り／バランス操作は採用していない。

- **マントリング**: ジャンプでは越えられない 0.75〜2.7m の段差の前で `Space`。縁を掴んで引き上げる。
  段差の上が棚になっている（先まで平らで歩ける）ときだけ成立するので、岩壁の途中では使えない。
- **トラバース**: 登攀中の横移動。移動量の水平成分が大きいと自動でトラバース表示になる。
- **落下**: 崖から踏み外す／スタミナが尽きる／`S` で手を放す。

### 斜度の3段階

| 斜度 | できること |
| --- | --- |
| 〜38度 | 歩いて登れる |
| 38〜54度 | **登って越えるしかない**。立って横切る・下ることはできる |
| 54度〜 | 立っていられない。ジャンプで飛び込んでも掴まれずに滑り落ちる |

歩けない斜面は必ず岩壁として登攀できる（同じ「進行方向の上昇率」で判定しているので、
「歩けないのに登れもしない」詰み斜面ができない）。判定はハイトフィールドの中心差分ではなく
進行方向 1.2m 先までの実際の上昇量で行う。テラスの縁で誤って足止めされないため。

## スタミナ

| | 内容 |
| --- | --- |
| 現在スタミナ | 短期的な運動能力。ダッシュ・登攀・ラッセルで減り、休憩で最大まで戻る |
| 最大スタミナ | 登山全体を通した疲労・身体状態。時間と環境で減っていく |

酸素・体温・疲労に独立したゲージは作らず、
**最大スタミナの減少量**と**現在スタミナの回復速度**への補正として表現する。

- 標高が上がると酸素が薄くなり、回復が鈍り疲労が早まる（`ENV.altitudeStart` 以上）
- 気温は 1000m あたり 6.5℃ 下がる。氷点下に近づくほど消耗が増える
- 運動強度（ダッシュ・ラッセル・登攀）が高いほど最大スタミナが削れる
- 岩棚（ledge）の上と地上での休憩で現在スタミナが回復する

## 登攀

このゲームの主要なルート選択要素。**岩肌を見て、登頂可能なルートを見つける**。

### 内部はグリッド、見た目は地形本体

岩壁は内部的に 2D グリッド（1セル 1.25m）へ分割し、各セルに登攀難易度を持たせる。
**グリッドそのものはプレイヤーに見せない。** 難易度は地形本体の傾斜・色と登攀中の HUD で伝える。

| 難易度 | ゲーム内の手がかり | 基礎消費 |
| --- | --- | --- |
| Easy | 休みやすく消費が少ないセル | 4 |
| Medium | 標準的な消費のセル | 9 |
| Hard | 消費が大きいセル | 19 |
| Impossible | 通れないセル | 通れない |

岩壁専用の別テクスチャや浮遊メッシュは重ねず、地形本体の表現をそのまま使う。
これにより、斜面から浮くオーバーレイや地形との二重描画を避ける。

地形の色と雪・踏み跡は地形メッシュ側で表現する。

```
消費 = セル難易度 × 移動方向 + 移動距離
移動方向: 登り ×1.0 ／ 横 ×0.82 ／ 下り ×0.58
```

難易度の割り当ては「登りやすさ」の連続場（縦に伸びる筋 + 横に走る帯）の**順位**で決めるので、
狙った比率をそのまま出しつつ、登攀中のセル選択とコストに連続性を持たせる。

手足や個々のホールド位置はゲームロジックでは扱わない。必要ならアニメーション側の話にする。

### 1手ずつ、方向を選んで登る

1. 岩壁に `W` を押し当てると壁に取り付く
2. `WASD` で手を出す方向を選ぶ（斜めも可）。狙っているセルに印が出る
3. `Space` で1手登る。**その先をどう繋ぐかは登りながら決める**
4. 抜け口まで届けば `W` + `Space` で乗り越える。**読み違えて力尽きれば落ちる**

隣が平滑で入れないときは、同じ方向へ手を伸ばして2マス先までを探す。
届く範囲は経路探索と同じ関数で決めているので、
**探索が「登れる」と判定したルートは、必ず方向キーだけで辿れる**。

出る情報は次の3つだけ。

| | |
| --- | --- |
| 選んでいる方向 | `↗` |
| その先のセルの難しさ | `難しい岩` ／ `並の岩（岩棚）` |
| 消費と残り | `消費 12 → 残り 64` |

その一手で力尽きるなら先に出る。承知で出すかどうかがプレイヤーの判断になる。

- **正解ルートは表示しない**。示すのは「その一手で何が起きるか」だけ
- 最短ルートが最適とは限らない。短いが難しい直登、遠回りだが簡単な線、途中で休憩できる線が同じ壁に同居する
- まっすぐ上へ押し続けても登り切れない。難しい岩を避けて岩棚を繋ぐ線を探す必要がある

### 岩棚は息を整える場所

| 場所 | 結果 |
| --- | --- |
| 壁の上へ抜けられるセル | `W` + `Space` でマントリングして歩行へ戻る |
| 岩棚 | 掴まって止まっている間スタミナが戻る（雪が乗っているので見て分かる） |
| 壁の下端 | `S` + `Space` で地面へ降りる |
| スタミナ切れ／`S` 長押し | 手が離れて落ちる |

### 生成と検査

1. セルごとに壁面の座標を求める（取れないセルは通行不可）
2. 難易度を「登りやすさ」の連続場の順位で割り当て、Easy の一部を岩棚にする
3. 到達可能性はグリッド経路探索で**検査のみ**行う。**岩肌の補修による突破保証はしない**
4. 登れない壁・工夫で登れる壁・巻くべき壁が混在してよい。山体全体として登山口から主峰へ到達できる構造は `reachability.ts` で検証する

## 山の生成

Seed と難易度から決定論的に生成する。同じ Mountain ID なら誰がプレイしても同じ地形になる。

```
Mountain ID = M<seedの36進数>-<難易度>     例: M000039U-3
```

### 骨格 → 肉付け

円錐や逆さ鉢ではなく、**MountainSkeleton** で先に山の骨を作る。

```
Seed
 ↓
MountainSkeleton (主峰・副峰・主稜・支尾根・鞍部・谷)
 ↓
Heightfield (肉付け・侵食・崖バンド・表面ノイズ)
 ├─ 3Dの山岳地形
 └─ 2Dの等高線地形図
```

どの方向から見ても中心へ一直線、にならないよう、主峰は中心からオフセットし、
複数の副峰・稜線ネットワーク・谷がルート選択を生む。

### スケールと解像度

| 定数 | 値 | 理由 |
| --- | --- | --- |
| `WORLD_SIZE` | **2000m** | 800m 級より広く、尾根・谷・回り込みを読める |
| `GRID_STEP` | **2m** | 1m のまま 4 倍にすると ~1600 万セルで重い。801²→1001² で旧と同程度 |
| `COARSE` | **4** (= 8m) | 骨格・緩成分は粗く評価し 3 次補間。崖バンドだけ細格子で掛ける |

生成要素:

- **骨格** 主峰 (中心からオフセット)・副峰・主稜線・支尾根・谷
- **前山・外周帯** 山体半径より外側の余白を、**低周波の連続起伏面** (fBm / ridged / 方向性排水) で埋める。線状の支尾根・浅い谷は骨格アクセントとして重ね、等高線と地図の補助線で読める。同心円のすり鉢ではなく、アプローチ方向に沿った緩い尾根・浅い谷・鞍部で「尾根を取る／谷を巻く」判断ができる。登山口から半径 30〜60m は歩き出しやすい低地を残し、その先へ自然に移行する。ワールド端へ向けて自然に下がる
- **肉付け** 尾根/谷ノイズ・麓の起伏・侵食的な凹み
- **崖バンド** 標高を段状にリマップ。「歩いて抜けられる弱点」と「登るしかない壁」が混在
- **岩質 / 表面 / 植生** 従来どおり

### 難易度

数値の強さではなく、山そのものが難しくなる。

| | 内容 | 山頂 | 歩きだけで登頂 | 歩きだけの到達高度 | 要登攀 |
| --- | --- | --- | --- | --- | --- |
| 1 ハイキング | 歩行中心。ときどき小さな段差 | 108m | 山による | — | 少 |
| 2 一般登山 | 急斜面と岩場。短い登攀と浅い雪 | 145m | 山による | — | 中 |
| 3 岩稜 | 長い登攀と積雪。ルートファインディングが要る | 178m | **できない** | 低 | 多 |
| 4 高難度 | 深雪と連続する岩壁 | 200m | **できない** | 低 | 多 |
| 5 最高難度 | どのルートを選ぶかが登頂可否を決める | 222m | **できない** | ごく低 | 多 |

`npm run test:terrain` で複数 seed の到達可能性を検証する。難易度3以上は歩行のみでは山頂に届かない。

生成した山は起動時に [reachability.ts](src/mountain/reachability.ts) で2通り検査する。

- **登攀あり**: 登山口から山頂へ到達できるか（できなければ警告）
- **歩行のみ**: 歩行とマントリングだけで登頂できてしまわないか（難易度3以上でできてしまえば警告）

### 積雪・ラッセル

積雪量は標高・傾斜・風下・地形の凹凸で変わる。専用操作はない。

- 積雪 18cm 以上を歩くと自動的にラッセルになる。移動が遅くなり、深さに応じてスタミナを消費する
- 未踏の深雪では**進行方向の雪**で判定するので、先頭は自分の踏み跡で楽をできない
- 通過した場所は「踏み跡」として残り、後続は消費が大幅に減る（実測: 先頭 8.2 → 後続 3.7）

登攀のロープと同じ原則:

```
ラッセル: 先頭が高コスト → 踏み跡 → 後続が低コスト
登攀:     先頭が高コスト → ロープ   → 後続が低コスト
```

これをマルチプレイにおける協力の中心システムとしている。

## マルチプレイ

協力マルチプレイが正式な仕様。シングルプレイは 1 人パーティーとして同じルールで動く。

タイトルでルーム名を入れると、**同じ山 + 同じルーム名**のプレイヤーと同じ部屋に入る。

サーバ（Durable Object）がゲーム状態の正となり、次を同期する。

- プレイヤーの位置・向き・状態
- 現在／最大スタミナ
- ロープ
- 踏み跡
- 登頂記録

静的な山岳地形は同期しない。Seed から各クライアントが生成する。

## 山の永続性

サーバには次を保存する。

```
Mountain ID / Seed / 難易度 / 山名 / 初登頂者 / 初登頂パーティー / 初登頂日時 / 登頂者数
```

- 未踏峰には正式名称がなく、`未踏峰 M000039U-3` と表示される
- 初登頂が成立すると、そのプレイヤーまたはパーティーに命名権が与えられる
- 一度命名された山は、以降すべてのプレイヤーに同じ名前で表示される（改名はできない）

```
src/
├── main.ts                       ゲーム本体 (シーン・ループ・各システムの結線)
├── core/
│   ├── math.ts                   clamp / lerp / damp / smoothstep
│   ├── rng.ts                    決定論的な乱数と勾配ノイズ (fBm / リッジ)
│   ├── types.ts                  共有型と調整値 (CLIMB / MOVE / STAMINA / ENV)
```

## 仕様からの相違点

**登攀中の上下移動を WASD に割り当てていない。**
仕様には「WASD: 移動／登攀中の移動」とあるが、方向キーでセルを自動選択すると
「候補の中から選ぶ」が「その方向に進む」に変わってしまい、
`W` を押しっぱなしにするだけでルートを登り切れてしまう。
ルートを見比べて選ぶ行為自体がこのゲームの中心なので、
登攀中のルート指定は**視点＋クリック**（＝仕様の「マウス: 登攀ルート選択」）に一本化した。
`S` は「手を放す」に割り当ててあり、操作キーは増えていない。
